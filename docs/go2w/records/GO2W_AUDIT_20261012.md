# Go2W 接入审计（2026-10-12）

## 源码与边界

- `source/robonix` 是无 `.git` 的交接快照；remote、branch、工作树 status 均不可读取。`SOURCE_VERSION.json` 声明基点 `62057c696cb49f01f14d9a4f16c9685e59b9e79b` 和已应用的 Executor lifecycle 补丁。不能把这份文件等同于 Git diff。
- `examples/go2w_read_only` 只有空目录，无代码、声明或测试。`examples/go2w_readonly` 是后续可运行版本：仅 mock JSON → health/state 与 health/stream；有来源/时间/失效侧车文件、3 个单元测试、构建/启动/停止脚本。二者没有重复文件；前者是未填充骨架，应暂时保留以便交接追溯。
- 独立克隆的 `source/robot-unitree-go2`：origin `https://github.com/syswonder/robot-unitree-go2.git`、`main`、`57e3758b2552d0be0e30af23c62a33c1f9a2cc8a`、克隆后干净。包含 pinned `unitree_sdk2`、`unitree_ros2`、Mapping、Navigation 子模块。
- 当前 vendor onboarding 要求机器人 deployment 独立于 Robonix 主仓库；原语通常独立成包，部署私有代码可留在 deployment。选择独立 `robot-unitree-go2w`，不改 Go2 默认行为，也不把完整 deployment 放进 `robonix/examples`。

## Go2 与 Go2W 差异 / 证据等级

| 项目 | Go2 参考实现 | Go2W 现状与处理 |
|---|---|---|
| SDK2 API | [代码确认] Go2 chassis 使用 `go2::SportClient`，含 Move/StopMove/ClassicWalk；控制被多重 gate 约束 | [官方确认] SDK2 有 Go2W 专属示例，使用相同 `SportModeState_` IDL，但示例还会调用 StandUp/Move 等，绝不可直接运行；Go2W 运动语义和 StopMove 效果[尚未确认] |
| robot state / DDS | [代码确认] Go2 读 `rt/sportmodestate`、`rt/lf/sportmodestate` | [真机确认] 本机 SDK2 在 `enp131s0` 收到 `rt/lf/sportmodestate` 与 `rt/lowstate`，低层 tick 递增；`rt/sportmodestate` 尚未试 |
| odometry / TF | [代码确认] Go2 从 SportModeState 生成 `/odom` 和 `odom→base_link` | [真机确认] Go2W high state position/yaw 可读，但设备 stamp 为 0；位置 frame、原点、速度定义、漂移、TF 发布方[尚未确认]，不能复用 Go2 odom 结论 |
| IMU | [代码确认] Go2 relay 输入 `/imu/data`，标准化 `/scanner/imu` | [代码确认] Go2W high/low IDL 均有 `imu_state`；真机目前仅打印过 high yaw，完整加速度/角速度单位与 frame[尚未确认] |
| LiDAR | [代码确认] Go2 以 `/utlidar/cloud` PointCloud2 输入，另有时间戳质量门 | [真机确认] 本机对候选 `rt/utlidar/cloud` 订阅 10 秒收到 0 帧，同时 high/low 为 100/4998 帧；实际发布路径、型号、QoS、点云字段和外参[尚未确认] |
| camera | [代码确认] Go2 独立 SDK VideoClient daemon + ROS bridge，曾记录 JPEG 不稳定 | Go2W 相机 API/流、标定、外参、帧率[尚未确认]；不能直接声称 RGB-D |
| ROS2 / QoS | [官方确认] Unitree ROS2 公开支持 Go2/B2/H1，文档列 Ubuntu 20.04 Foxy 和 22.04 Humble；Go2W 未单独列出 | [真机确认] 拓展坞有 Foxy，但笔记本无 ROS2；Go2W 的 ROS2 topic/type/QoS[尚未确认]，优先本机 SDK2 原生订阅 |
| wheel-leg | Go2 是四足步态平台 | [官方确认] Go2W 有专属 SDK 示例；轮腿模式、轮速/关节对应、底盘控制差异[尚未确认]，禁止套用 Go2 运动配置 |
| 网络 / 时间 | [代码确认] Go2 部署需要专用 NIC、domain 0，启动脚本绑定 CycloneDDS | [真机确认] `enp131s0=192.168.123.99/24` DDS 可接收；高层设备 stamp=0，拓展坞时钟先前为 1970；源时间新鲜度与同步[尚未确认] |

## Go2 deployment 可复用性

可借鉴：独立 manifest/Soma 组织、`allow_motion=false` 默认、SDK 与 ROS 进程隔离、回环监听、生命周期与 read-only 测试。不能直接复用：Go2 URDF/footprint/frame、Go2 专属 chassis gate 和导航 profile、Go2 传感器 topic、旧 pinned SDK/ROS2 版本。Go2 `scripts/validate_offline.sh` 在本机完成大量静态/单元检查，但在 strict JPEG 测试处因缺少 `jerror.h`/`jpeglib.h` 退出 1；这不是 Go2W 兼容性通过或失败的证据，不进行 sudo 安装。

## 本轮决策

独立部署优于让 Go2 deployment 直接兼容 Go2W。先只读、本机运行、复用现有 health mock 作为合同/生命周期参照；未经确认的 charging、odom、TF、LiDAR、camera 不发布为真实标准能力。优先接通原始 SDK2 状态到本机只读采集，再逐字段完成可核实映射。运动 gate 保持关闭，机载端不改动。

## 本机实测增量

`source/robot-unitree-go2w` 的十秒 SDK2 只读采集编译通过，真机退出码 0。首轮 low/high 均有数据，第二轮 high=100、low=4998、候选 cloud=0。第二轮 low 样本 `power_v≈29.51`、`bms_soc_percent=58`、`bms_status_raw=8`；high `device_stamp_sec=0`、`device_stamp_nanosec=0`、`mode=1`、`error_code=0`。`bms_status_raw` 仅原样记录，不解释充电语义。现有 `go2w_readonly` 3 个单元测试和 `rbnx validate` 均通过，但都只覆盖 mock，尚无真实 Robonix provider 注册证据。

## Robonix commissioning 验证

独立目录已建立本地 Git 仓库，未提交；七个新文件以 intent-to-add 保留可审计 `git diff`。mock-only 清单引用交接包中的 `go2w_readonly`，并使用明确标为 commissioning 的单 link URDF；这不是可发布的完整本体部署。

`rbnx build -f robonix_manifest.yaml --no-update-check` 成功：1 个 primitive 构建。笔记本回环网络许可下 `rbnx boot` 成功启动 Atlas `127.0.0.1:55051`、Executor `:55061`、Soma `:55091`，`go2w_health_mock` 为 ACTIVE。`rbnx caps -v` 确认 health/state、health/stream 及 lifecycle 在 Atlas 注册；随后 Ctrl-C 正常停止三个系统进程。本测试全为 mock，与 SDK2 真实数据采集是两条尚未连接的链，**不得声称 Robonix 已读取真机 health/odom/IMU**。

## 真实 camera snapshot 增量

本机 SDK2 `VideoClient::GetImageSample` 一次性只读调用返回 0、210333 字节 JPEG；没有保存图像。独立 Go2W 目录中的 `packages/go2w_camera_snapshot` 使用现有 `robonix/primitive/camera/snapshot` 合同：单次 SDK 读取 JPEG，在进程内验证并解码成 `rgb8`。设备图像无已核实源时间/optical frame，返回 header stamp=0、frame_id 为空，不能给几何/导航使用。进程仅运行在开发笔记本；机载端无部署。`GO2_ALLOW_MOTION=false`，没有运动 publisher 或 SportClient。

`rbnx validate packages/go2w_camera_snapshot`、`bash build.sh` 和三个离线单元测试通过。通过 `bash start.sh` 启动时，相机原语在 Atlas 注册为 ACTIVE，`rbnx caps -v` 列出 snapshot MCP capability。对回环 MCP 端点实际调用成功，返回 `1920×1080 rgb8`、`step=5760`，base64 解码后为 `6,220,800` 字节，恰为 `width×height×3`；重复调用亦通过。日志确认相机 lifecycle gRPC 与 MCP HTTP 均只绑定 `127.0.0.1`，mock health lifecycle 也只绑定回环。所有进程已通过 Ctrl-C 停止。

这证明的链路仅是 `Robonix camera/snapshot → 本机 Go2W provider → 本机 SDK2 → Go2W → 单帧 RGB`。不证明真实 health、IMU、odometry、LiDAR、TF，也不证明 Pilot/Executor 已实际调用 snapshot；部署仍使用 mock health 和 commissioning-only 单 link URDF，不可发布为完整 Go2W 本体。
