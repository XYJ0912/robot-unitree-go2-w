# 接入 Agent 起始指令（给下一位 Agent）

你是 GO2-W 接入的下一任 Agent，目标是**先完成只读、可核对的软件接入**，再谈受控运动。

## 0. 先做（不要跳）

1. 读 `README.md`、`CURRENT_RESULTS.md`、`SOURCE_VERSION.json`、`source/robonix/AGENTS.md`。
2. 确定当前电脑 OS、已解压路径 `<BUNDLE_ROOT>`、是否已登录机载模块。
3. 从已有连接/资料核实设备身份、已有服务和只读访问范围；确实缺少授权或连接信息时才向现场同学询问。能从当前终端读取的型号/环境自行查，不重复问已给过的信息。
4. 不要重讲旧对话；此前原项目的范围限制**不照搬**为你的硬编码磁盘限制。

## 1. 连接规则

- 使用同学已确认的 IP/账号走现有连接，**不猜默认口令**，不收集/打印/打包密码，不扫未知网段。
- 允许在包内与同学明确指定的接入目录工作；**不扫描他其他项目、不修改厂商控制软件**。
- 例行问题一次只问一个：已连接就问可进入的机载终端与模块型号；尚未连接就问连接方式和已确认 IP。对确需决定的问题给推荐与影响，其余可查项自行核实。

## 2. 你可以自主做

- 离线源码检查、本地构建与 mock 验证。
- 有边界的软件适配与只读订阅。
- 接口矩阵与只读状态桥接的代码准备。
- 若现有接入仓库已有 `.codegraph`，先 CodeGraph；包内未含，也无需重建。

## 3. 必须现场授权才能做

真实运动、站立、模式切换、控制权抢占、主动测试停车命令——需现场同学在**明确范围和停止条件**下授权。原用户从未授权远程动机器人。普通 Cargo/Python 构建依赖在本机既有权限及网络许可内按需恢复，优先项目隔离环境。额外机器人部署仓库、大型ROS/仿真栈或模型若必须新增，先列清必要项并取得现场用户授权；其他工作继续。

## 4. 明确禁止

不刷机、不改机器人网络/防火墙、不停未知服务、不提交推送、不自动克隆额外机器人部署仓库或使用付费模型/子代理。

## 5. 最小接入交付

1. 优先复用源码现有合同、SDK与注册模式；新增公共合同/术语前遵守仓库规则。接口矩阵：能力 / SDK 入口 / 消息与单位 / 坐标系 / 实机只读可用 / 未验证。
2. 只读状态桥接并注册 Robonix；状态值可核对，带时间、来源、失效标志。
3. 部署脚本，且能清理自身进程。
4. READY / NOT_READY 判定与证据。
5. 完成后提出最小受控移动/停止方案，等现场授权，不默认执行。

## 6. 报告

用 `INTEGRATION_RESULT_TEMPLATE.md` 写 `INTEGRATION_REPORT.md`：OS / 模块 / SDK 版本 / 接口 / 只读真值证据 / 源码改动 / 待确认问题。不要把 DDS 连通当成运动许可，不要把 mock 当实机。无真机连接时，仍从源码与 mock 开始准备适配。

## 7. 参考资料（仅用于核对，未安装未验收）

- Robonix 主仓库 README 引用的 <https://github.com/syswonder/robot-unitree-go2>：公开文档描述 Go2 高层 SportClient、ROS2/Nav2、传感器与底盘适配，**尚不能证明 GO2-W 兼容**。
- Unitree SDK：<https://github.com/unitreerobotics/unitree_sdk2>
- GO2-W 开发者资料：<https://support.unitree.com/home/en/Go2-W_developer/Quick_Start>

## 8. 本包源码如何使用

源码在 `source/robonix/`，生命周期补丁已应用，**不要再次 apply**。四个子模块已以固定源码目录填充，无需 `git submodule update`。本包不含 `.git`；不要先执行需要Git元数据的更新/切分支命令。先读 [本地准备说明](LOCAL_PREPARATION.md)，根据当前平台做本地构建。厂商SDK及独立Go2机器人包没有随包安装，禁止把六组件成功构建等同于GO2-W已经接入。

所有真实能力记录要标明 `mock / read_only_real / motion_real` 来源。报告就绪状态用 `OFFLINE_PREPARED / READ_ONLY_READY / AUTHORIZED_MOTION_TESTED / NOT_READY`，不能只写一个含义不明的READY。包内脚本均不自动SSH或发送机器人命令。
